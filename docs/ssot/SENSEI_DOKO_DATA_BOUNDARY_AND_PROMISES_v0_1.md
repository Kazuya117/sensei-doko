# 先生いまどこ？ DATA BOUNDARY AND PROMISES v0.1 (DRAFT 2026-10-23)

## 第 1 章 あずかる情報（4 種類だけ）

| ID | 情報 | 中身 | 何に使うか | 所在 |
|---|---|---|---|---|
| S2-1 | Google アカウント情報 | メールアドレス・名前・プロフィール画像 URL | 本人確認と、学校アカウントかどうかの確認だけ | Supabase Auth・`public.profiles`（メールアドレスは持たない） |
| S2-2 | 先生が自分で入力した情報 | 表示名・ひとこと・いまの状況・参加 / 一時停止 | 生徒への表示 | `public.td_teachers` |
| S2-3 | 探した記録 | どの先生を・どんな用件で・いつ探したか・会えたか・届いた報告の数。**場所は含まない** | 依頼の表示・分析 | `public.td_searches` |
| S2-4 | 見かけた報告 | 先生・場所・おおよその時間 | 探している生徒への通知 | `public.td_sightings`（2 時間） |

上記以外を集めない。行動履歴・位置情報（GPS）・端末情報を集めない。

## 第 2 章 誰が何を見られるか（DB の権限で強制）

| ID | 情報 | 探している生徒 | 先生本人 | 報告した生徒 | 他の生徒 | 運営チーム |
|---|---|---|---|---|---|---|
| S2-5 | 誰がどの先生を探しているか | 本人の分だけ | **人数と用件の種類だけ**（誰かは見えない） | 見えない | 見えない | 見えない（`td_searches` の comment） |
| S2-6 | 見かけた報告（場所） | 自分の依頼に対する分 | 自分の分 | 自分が出した分 | 見えない | 見えない |
| S2-7 | 誰が報告したか | 見えない | 見えない | — | 見えない | 見えない（AP-5） |
| S2-8 | 校内マップ（`td_places`） | ログインした人全員 | 同左 | 同左 | 同左 | 同左。**repo には含めない** |
| S2-9 | 参加している先生の一覧 | `participating = true` の先生だけ | — | — | 同左 | 同左 |

## 第 3 章 先生についての約束（AP-3〜AP-6 の具体）

| ID | 約束 | 強制の所在 |
|---|---|---|
| S2-10 | 探せるのは、自分でログインして「参加する」を選んだ先生だけ | `td_teachers` の行が本人 insert でしか作れない（`sensei_doko_rules`） |
| S2-11 | 「いまは探さないで」を理由なしにいつでも設定できる。その間は探すことも報告することもできない | 同上（paused 時の insert 拒否） |
| S2-12 | 場所を知らせられるのは、誰かがその先生を探しているときだけ | `td_sightings` の insert 条件 |
| S2-13 | 報告は 2 時間で見えなくなる。探した記録に場所を残さない | select 条件（2 時間）・`td_searches` に場所列が無い |
| S2-14 | 選べる場所は登録済みの校内の場所だけ。保健室などは選べない | `td_places.selectable = false` |
| S2-15 | 使えるのは月〜土の 7〜19 時。探すのは 1 日 10 回まで。同じ先生の報告は 10 分に 1 回まで | `private.td_school_hours()`・insert 時の回数制限 |
| S2-16 | 先生は、自分についての報告を見て消せる。参加をやめると自分の情報はすべて消える | `td_sightings` の delete 権限・`td_teachers` の delete |

## 第 4 章 生徒についての約束

| ID | 約束 |
|---|---|
| S2-17 | 誰がどの先生を探しているかは、他の生徒に見えない。先生に届くのは人数と用件の種類だけ |
| S2-18 | 誰が場所を知らせたかは、誰にも表示されない |
| S2-19 | 利用者側の約束: うその場所を知らせない。先生を追いかけたり、休憩中に呼び止めたりするために使わない（これは DB で強制できない。運営の規律） |

## 第 5 章 保持と削除

| ID | 対象 | 保持 | 削除のしかた | 実測 |
|---|---|---|---|---|
| S2-20 | 見かけた報告 | 2 時間 | 2 時間で見えなくなり、「次の報告のときに削除される」（`td_sightings` の comment） | **削除経路は未確認**。README の `sensei_doko_deletes` は存在しない（Charter Q-3）。確定するまで利用者に「削除される」と述べない |
| S2-21 | 探した記録 | 未定 | 場所を含まない。保持期間の定めなし | UNKNOWN（Charter Q-6 とあわせて決める） |
| S2-22 | 先生の情報 | 参加している間 | 参加をやめると削除 | `deleteTeacher`（app.js）・DB 側の連鎖削除は未確認 |
| S2-23 | 生徒のアカウント | 利用期間 | 運営チームに伝えて削除 | 手順は SSOT-3 |
| S2-24 | すべてのデータ | 探究活動の終了まで | 終了時に全削除 | **日付・手順は未定**（Charter Q-6） |

## 第 6 章 アクセス境界

| ID | 条項 | 実測（2026-10-23） |
|---|---|---|
| S2-25 | ログインは学校の Google アカウント（ドメインは `app.js` に定義）と、`private.allowed_emails` で個別に許可したアドレスだけ | README・app.js 123 行 |
| S2-26 | `public.td_*` の 4 表はすべて RLS 有効 | Supabase API |
| S2-27 | `private.*` の 4 表（`allowed_domains` / `moderator_emails` / `allowed_emails` / `teacher_emails`）は RLS 無効 | Supabase API の警告。**API 公開スキーマに `private` が含まれるかは未確認**（Charter Q-5）。含まれていなければ外部から到達できない。確認前に RLS だけ有効化しない（管理機能が止まる恐れ） |
| S2-28 | `app.js` に書かれた Supabase キーは公開用（publishable）。秘密キーを repo に置かない | README |
| S2-29 | 保存先は Supabase（東京リージョン）。これ以外の外部サービスにデータを送らない | app.js の外部接続は Supabase のみ（Charter A-5） |
